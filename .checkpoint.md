# CHECKPOINT — Contexto para o assistente

## Projeto
**XeMonitor** — Aplicação Zig que lê scanner Honeywell 1900 (Granit) via CH340 (USB-Serial) e injeta como teclado no Windows.

## Hardware
- Scanner: Honeywell 1900 (Granit) via adaptador CH340 USB-Serial
- Porta Windows: COM4 (o driver CH340 no Windows está quebrado — erro 31 / AccessDenied)
- Fluxo ativo: **WSL2 bridge** — WSL2 (**Alpine/OpenRC/musl**) lê `/dev/ttyUSB0` e serve TCP na porta 9000; o Windows conecta com `--tcp` e injeta via `SendInput` (Win32 nativo)

### Limpeza no CachyOS
- **Conflito de porta 9000**: existia um unit **systemd de sistema** legado (`/etc/systemd/system/xemonitor-bridge.service`, bridge antigo `/usr/local/bin`, root, `Restart=always`) que respawnava e tomava a porta do unit de usuário. Resolvido: `systemctl disable --now xemonitor-bridge` (unit de sistema). Agora o único bridge é o **unit de usuário** (binário novo do repo).

## Problema original (histórico, NÃO RESOLVIDO no Windows)
Driver CH340 no Windows corrompido: `SetCommState` erro 31, libserialport AccessDenied, PuTTY erro 5. Contornado pelo TCP bridge WSL2. Se um dia quiser voltar ao acesso direto, é preciso reinstalar/diagnosticar o driver CH340.

## Sessão no CachyOS (Linux host de dev/teste) — CONCLUÍDO
- **Fix TCP** em `src/main.zig` (arm `.tcp`): `rbuf [0]u8` — o `netRead` do Zig anexa o buffer interno do reader como 2º iovec; com reader novo por byte, o byte extra era descartado → `'TSSA00'`. Com rbuf vazio, lê só o destino. Provado com fake server e scan real.
- **End-to-end no Linux (systemd)**: unit de usuário `~/.config/systemd/user/xemonitor-bridge.service` com `ExecStart=/usr/bin/sg uucp -c '<repo>/zig-out/bin/bridge'` (wrapper dispensa re-login — sessão antiga não herdou grupo `uucp`). `systemctl --user enable --now` → active, `/dev/ttyUSB0` aberto, porta 9000.
- **Scan físico validado 2x** (`7898121840147`): `[scan] '<código>'` completo → `[info] injected` → `[info] enter sent` → texto no **Kate** (foco obrigatório: ydotool digita onde está o foco; o log `injected` não garante foco no editor).
- **Bridge é musl estático** (Zig linka musl por padrão): `readelf` sem dynamic interpreter → roda em glibc e musl (Alpine) sem recompilar.
- Observação: `runCommand` no main.zig não checa exit code do ydotool — `injected` não é prova de entrega ao alvo (ok, pois o alvo depende de foco).

## Sessão instalação Linux — decisões + roadmap (v0.8.0)

> Contexto: usuário reportou que `install.sh` "completa" mas não funciona. Análise
> de todo o histórico + diff de comportamento em CachyOS (KDE Wayland).

### Decisões de design (registradas em 2026-08-29)

- **B2 (manter dois caminhos oficiais)**: `install.sh` (system unit, bridge como
  root) é o caminho padrão novo. `run_xemonitor.sh` (user unit, `sg uucp`) é a
  alternativa. GUI detecta qual existe e ajusta `server_mode` automaticamente.
- **B2 refinado (askpass)**: GUI Linux em `systemd-system` usa askpass na ordem
  `ksshaskpass` (KDE) → `zenity` → `yad` → terminal (`xterm`/`konsole`/
  `gnome-terminal`) rodando `sudo -v` → instrução manual. Sem dependência de
  polkit/pkexec.
- **B3 (DTR/RTS)**: `ioctl`/`TIOCMBIS` é syscall do kernel (não pacote).
  Dependência real = root (system) ou grupo (user) + driver `ch341` carregado.
  Em CachyOS o módulo `ch341` já vem no kernel padrão. Bridge agora confirma
  via `TIOCMGET` se DTR+RTS ficaram setados e loga o driver ativo.
- **B4 (GUI em Alpine)**: install detecta libc e pula GUI/desktop entry/autostart
  em musl (Alpine). Bridge e CLI continuam. Binário GUI é glibc.
- **A2 (logout)**: install detecta grupos não-efetivos (`id -Gn` vs
  `getent group`) e exibe banner amarelo em 3 pontos. Instrução de logout é
  destaque, não aviso.
- **A3 (teste injeção)**: removido do install (pouco confiável em TTY/SSH).
  Vai para `xemonitor-diagnose --test-serial`, rodado sob demanda pelo usuário.
- **B1+B5 (autodetect device)**: bridge tem `autoDetectSerial()`:
  `/dev/serial/by-id/*` → `/dev/ttyUSB*` → `/dev/ttyACM*` → `/dev/ttyUSB0`.
  Override via `--device <path>`. Install grava o resultado em
  `/etc/xemonitor/device`; units fazem source do file.

### Plataformas-alvo (ordenadas por prioridade)

1. **CachyOS (KDE Wayland)** — primário. Validação E2E obrigatória antes do
   release. Tem `ch341` no kernel, `ydotool` em `[extra]`, `ksshaskpass` nativo.
2. **WSL2 (Alpine/OpenRC e Arch/systemd fallback)** — TODO pós-v0.8.0. Bridge
   precisa `usbipd attach` antes; install.sh não roda no WSL host. Validar que
   o autodetect funciona via `by-id` no Alpine (udev ativo).

   (flag CLI já existe). Documentar `--device /dev/ttyUSB0` e o módulo
   `ch341` faltando em imagens mínimas.
